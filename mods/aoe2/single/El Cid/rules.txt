; coding: utf-8
; Campaign-local rules for the AoE2 DE "El Cid" campaign.
;
; Source of truth: the Age of Empires Series Wiki scenario pages for
; "Age of Empires II: The Conquerors/El Cid" (Brother against Brother,
; The Enemy of my Enemy, The Exile of the Cid, Black Guards, King of
; Valencia, Reconquista).
;
; The campaign is the first in AoE2 to switch civilization between
; scenarios: Spanish in ch. 1-2, Saracens in ch. 3-4, Spanish again in
; ch. 5-6. The player colour is red throughout.
;
; All NPCs below are story units: they must never aggro on sight and
; must never counterattack, otherwise they chase the player's units and
; issue meaningless attacks (the same trap npc_joan / npc_dauphin in the
; Joan of Arc campaign fell into -- see that file for the long version).

; ---------------------------------------------------------------------
; npc_cid -- Rodrigo Díaz de Vivar, "El Cid", on foot.
;
; The hero unit of the whole campaign. AoE2 DE gives him 330 HP, 13
; melee attack, +3 vs buildings, 5 line of sight and regeneration of
; 0.5 HP/s (30 HP per minute); he cannot be converted.
;
; Inherits ``militia`` (an INFANTRY unit) so that his MOVEMENT SOUND is
; the human footstep, not the cavalry clomp: the footstep noise is taken
; from the STYLE layer (``style.get(type_name, "move")``), and the
; knight/aoe_knight styles carry ``move 1303 1303`` -- the horse-hoof
; sound.  Before he mounts Babieca he walks, so he must walk like an
; infantryman.  The mounted form (``npc_cid_mounted``) keeps the
; cavalry style and therefore the hooves.
;
; He is deliberately NOT a full combat hero: this engine has no hero
; regeneration or "cannot be converted" flag, so those two properties
; of the original hero unit are not reproduced. What the campaign
; needs from him is that he is a must-survive key unit.
;
; hp_max 330 and mdg 13 match the DE hero unit; mdf/rdf 2 / rdg 0
; match his DE armour line (armor 2, pierce armor 1, no ranged attack).
; agro_on_sight 0 + counterattack_enabled 0 keep him from charging
; into the enemy on his own -- in the original he only fights what the
; player points him at.
; ---------------------------------------------------------------------
def npc_cid
is_a militia
; The mod's legacy ``knight`` stub carries ``decay 1`` (1000 ms), which
; would make the hero disappear one second after he spawns.  The
; campaign hero must never expire, so the inherited decay is cancelled.
decay 0
; The hero is a story unit, never a trainable one: the militia line
; would otherwise make him cost 20 gold / 50 food and take 21 s to
; train.  Both are cancelled explicitly.
cost 0 0 0 0
time_cost 0
; The militia line upgrades into man_at_arms (``can_upgrade_to
; man_at_arms``).  Inheriting that would make ``apply_unit_line_upgrade``
; morph the hero into a generic Man-at-Arms the moment the player
; researches it -- the campaign's key unit would simply disappear.
; An empty declaration cancels the inherited list.
can_upgrade_to
; The militia line also lists the whole infantry blacksmith / age tech
; list (forging, squires, scale_mail_armor, ...).  The hero is not one
; of the player's militia: he must not inherit their upgrade effects,
; so the list is cancelled as well.
can_use_tech
hp_max 330
sight_range 5
; The hero's own speed and melee reload are stated explicitly so that
; they can never be lost again, whatever parent he inherits from:
; without an explicit ``speed`` the unit ends up with
; ``Creature.speed == 0`` and every move order fails instantly (see
; ``move_to_or_fail`` in soundrts/worldorders/base.py).  Without an
; explicit ``mdg_cd`` the hero would swing once per simulation tick
; instead of once per reload.
;
; DE values used: the hero walks like a heavy infantryman (0.96, the
; speed of long_swordsman / man_at_arms) and his melee reload is the
; standard 2 s of the Spanish melee line.
speed 0.96
mdg 13
mdf 2
rdf 2
rdg 0
mdg_cd 2
mdg_range 1
agro_on_sight 0
counterattack_enabled 0

; ---------------------------------------------------------------------
; npc_cid_mounted -- El Cid Campeador, the same hero once mounted on
; Babieca (his horse).
;
; The DE campaign literally swaps the on-foot El Cid for the mounted
; El Cid Campeador once he reaches the stable, and both are key units.
; The mounted version is the stronger of the two (same 330 HP, but the
; campaign treats him as the version that leads the army).
; ---------------------------------------------------------------------
def npc_cid_mounted
is_a knight
; Same as npc_cid: cancel the inherited ``decay 1`` of the legacy knight
; stub, otherwise El Cid Campeador vanishes after one second.
decay 0
hp_max 330
sight_range 6
; Same inheritance trap as npc_cid: the legacy ``knight`` stub has no
; ``speed`` and no ``mdg_cd``, so both have to be stated explicitly.
; Mounted on Babieca the hero rides at cavalry speed (1.35, same as
; aoe_knight) and his melee reload is the cavalry one (1.8 s).
speed 1.35
mdg 13
mdf 2
rdf 2
rdg 0
mdg_cd 1.8
mdg_range 1
agro_on_sight 0
counterattack_enabled 0

; ---------------------------------------------------------------------
; npc_alfonso -- King Alfonso VI of León and Castile.
;
; A separate player in the original campaign: once the player's army
; destroys his castle, the king himself becomes controllable and must
; be brought to King Sancho. He is a key unit -- losing him loses the
; scenario.
;
; He is a ruler, not a soldier, so he must not fight: same
; no-aggro / no-counterattack / zero-damage pattern as npc_dauphin in
; the Joan of Arc campaign.
; ---------------------------------------------------------------------
def npc_alfonso
class soldier
hp_max 200
; The king must survive his own castle's siege.  In chapter 1 he
; belongs to ``computer3`` (alliance 2, the ENEMY side) and stands on
; the same square as his castle at b5, so the player's assaulting
; units auto-target him and kill him -- which trips
; ``(key_unit_killed npc_alfonso) (defeat)`` and makes objective 4
; (escort him to King Sancho) unreachable.
;
; ``is_vulnerable 0`` removes him from ``known_enemies``
; (soundrts/worldplayerbase/perception.py), so the player's units
; never pick him as a target.  ``receive_hit`` honours the same flag
; (soundrts/combat/damage_effects.py), which also protects him from
; splash / bounce / pierce damage that does not go through the
; targeting code at all.
;
; He stays fully controllable: he can still be selected, transferred
; to the player and ordered to walk.
is_vulnerable 0
; ``class soldier`` (the plain Python base class) has NO movement speed
; at all -- ``Creature.speed`` defaults to 0.  A unit with speed 0 can
; never be ordered to move, so King Alfonso could not be escorted to
; King Sancho and objective 4 of chapter 1 (and objective 2 of chapter
; 4) could never be completed.  He walks like a common soldier
; (1.0, the speed of the spearman line).
speed 1.0
mdg 0
mdf 0
rdf 0
rdg 0
agro_on_sight 0
counterattack_enabled 0
receive_items 0

; ---------------------------------------------------------------------
; npc_wonder -- the Wonder the Valencians build in ch. 5.
;
; The base game defines a ``wonder`` building (res/rules.txt) with
; ``victory_time 300``: as soon as it is finished the OWNER wins the
; game by itself, with no objective bookkeeping.  That is the wrong
; model for this chapter -- the DE original ends when the Valencians
; finish the Wonder while the player is still defending Valencia, and
; the Wonder must survive the whole siege.
;
; The AoE2 mod's own rules.txt starts with ``clear``, so the base
; ``res/rules.txt`` definitions are wiped and there is NO ``wonder``
; class to inherit from (``is_a wonder`` would raise "wonder doesn't
; exist" and leave ``rules.unit_class("npc_wonder") == None``, which
; makes ``(add_units k2 1 npc_wonder)`` spawn nothing at all).
;
; So the campaign defines its OWN ``npc_wonder``:
;   * it is a plain ``building`` (the mod has no wonder class), with
;     the wonder artwork coming from ui/style.txt (``is_a wonder keep``),
;   * it has NO ``victory_time`` -- the chapter's victory is driven by
;     the trigger script (see 5.txt), not by the generic
;     building-victory timer, and
;   * it is a plain scenario prop: no cost, no population, not
;     repairable, and it does not aggro.
;
; The chapter watches it with ``(building_lost npc_wonder)`` for defeat
; and a 10-minute timer for victory.
; ---------------------------------------------------------------------
def npc_wonder
class building
is_a building
hp_max 6000
cost 0 0 0 0
time_cost 0
mdf 8
rdf 8
agro_on_sight 0
counterattack_enabled 0
population_provided 0
is_repairable 0
; The base ``wonder`` has ``victory_time 300``; the engine only copies a
; parent attribute when the child does not define it, so writing 0 here
; cancels the inherited auto-victory countdown.
victory_time 0

; ---------------------------------------------------------------------
; npc_cid_body -- the dead El Cid, propped on Babieca in front of the
; castle of Valencia in ch. 6.
;
; In the DE original the body of the Cid is strapped to his horse so
; that the garrison of Valencia does not learn he is dead.  If this
; unit is killed, the soldiers lose heart and the scenario is lost --
; hence the ``(key_unit_killed npc_cid_body) (defeat)`` trigger in
; 6.txt.
;
; It is a key unit, so it must have a ``title`` in ui/style.txt
; (9270-9286 block): without one, ``EntityView.short_title`` is empty
; and the unit can neither be Tab-selected nor targeted.
; ---------------------------------------------------------------------
def npc_cid_body
is_a npc_cid_mounted
decay 0
hp_max 330
sight_range 4
; The corpse inherits npc_cid_mounted's cavalry speed -- it must NOT:
; the dead Cid is strapped to Babieca and has to stand still in front
; of the castle of Valencia.  ``speed 0`` cancels the inherited value.
speed 0
mdg 0
mdf 0
rdf 0
rdg 0
agro_on_sight 0
counterattack_enabled 0
receive_items 0
