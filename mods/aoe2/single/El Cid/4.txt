; ---------------------------------------------------------------------------
; EL CID -- the player.  He starts in the west at c3 with a small army.
;
; THE TOWN CENTER IS THE KEYSTONE OF THIS WHOLE START.  It is the only
; building whose ``storable_resource_types`` covers all four resources
; (rules.txt:5256) -- ``workshop``, ``aoe_castle``, ``scouttower`` and
; ``shipyard`` store NOTHING.  Without a Town Center:
;   * ``nearest_warehouse`` returns None for every resource, so the
;     villagers cannot deposit a single thing (probe: all four resources
;     came back None before this fix, and ``town_center()`` for all four
;     in chapters 5/6);
;   * ``available_population`` is 0, so not even a House can be built;
;   * ``house`` / ``mill`` / ``lumbermill`` / ``mining_camp`` / ``barracks``
;     all have ``requirements town_center``, so no economy building and
;     no barracks can be raised;
;   * only the Town Center can ``can_advance`` to the next age, so the
;     player would never leave the Dark Age and could never build a
;     Siege Workshop -- which is exactly why there were NO SIEGE
;     ENGINES in this chapter.
;
; Age chain: ``dark_age`` / ``feudal_age`` / ``castle_age`` must ALL be
; listed, even though the chapter starts in the castle age:
;   * ``Player.has()`` looks the name up in ``player.upgrades``, so
;     ``requirements castle_age`` (workshop, battering_ram, mangonel)
;     is satisfied directly;
;   * ``castle_age`` itself requires ``feudal_age``, which is checked by
;     literal name, so ``feudal_age`` must be listed too.
; The DE original's chapter 4 is a Castle Age scenario -- El Cid besieges
; Yusuf's castle with a full siege train.
;
; Starting resources (800 wood / 600 gold / 500 food / 400 stone):
; a Town Center costs 275 wood + 100 stone, four Houses 100 wood, the
; Barracks/Stables/Siege Workshop 175+175+200 wood -- 925 wood in all,
; so the player can raise the whole base immediately AND still afford
; siege engines (a Battering Ram is 75 gold + 160 wood).
;
; The army follows the DE original's starting units (2 Scorpions, 2 Monks,
; 4 Long Swordsmen, 4 Conquistadors, 6 Pikemen, 6 Knights, El Cid) and
; adds the siege train the DE walkthrough recommends for walled cities
; ("try using Trebuchets and garrisoned Battering Rams against them"):
; the Trebuchet out-ranges the castle's 8-tile arrow range with its 16,
; so it can shell the castle from safety.
;
; Population: town_center (+5) + 6 house (+30) = 35 housing from the
; buildings, and the starting units cost 1 + 8 + 8 + 6 + 12 + 2 + 4
; + 4 + 4 + 3 = 52.  ``population 30`` adds a scenario population
; bonus on top of the buildings so that the player is NOT over the
; cap at the very first tick (52 used vs 35 housing would block every
; training order with ``order_impossible,not_enough_population``).
; The player still has to build more houses as the army grows.
; ---------------------------------------------------------------------------
player 800 600 500 400 c3 1 town_center 1 barracks 1 stables 1 workshop 6 house 1 npc_cid_mounted 4 conquistador 4 mameluke 6 pikeman 6 aoe_knight 2 monk 4 peasant 2 battering_ram 2 mangonel 1 trebuchet dark_age feudal_age castle_age population 30

;
; The TOWN CENTER is what makes the handover useful: without it the
; player would receive four villagers who cannot deposit anything (the
; two watchtowers and the two knights store no resources either).
; The CASTLE lets the player build Trebuchets afterwards.
;
; DE original, Standard difficulty: "King Alfonso's base has a Castle,
; which will be given to the player with the rest of his base."
;

; covers "easy" and "standard" (easy is the equivalent of the DE's Story
; mode, which is even more generous than Standard):
;
;   * Easy / Standard -- the castle is GIVEN to the player with the base
;   * Moderate        -- no castle (the player must build his own)
;   * Hard            -- no castle
;
; The engine supports this via the ``(difficulty <level>)`` /
; ``(difficulty <op> <level>)`` trigger condition -- see
; soundrts/worldplayerbase/triggers.py::lang_difficulty.
;
; The town center, the two houses, the two watchtowers, the four
; peasants and the two knights are handed over at EVERY difficulty.

; ---------------------------------------------------------------------------
; STANDARD-DIFFICULTY BONUSES (AoE2 DE "Black Guards").
;
; DE original: "On Standard difficulty, King Alfonso's base has a Castle,
; which will be given to the player with the rest of his base, and the
; player begins with Murder Holes researched."
;
; Two things are therefore granted on the "standard tier" of the
; difficulty -- the ``story`` semantic tier, which covers "easy" and
; "standard" (easy is the equivalent of the DE's Story mode, which is
; even more generous than Standard):
;
;   1. The CASTLE in Alfonso's camp (a1).  It is NOT part of the
;      ``computer_only`` line any more -- it is added here by a trigger so
;      that it appears only on the standard tier.  On Moderate and Hard
;      the player has to build his own castle, exactly like the DE
;      original.
;
;   2. The MURDER HOLES tech for the player.  Researching it at start
;      makes the watchtowers and the castle the player inherits stop
;      having a minimum range (the tech's effect is
;      ``bonus rdg_minimal_range -1`` on scouttower/cannontower/aoe_castle).
;      Because the tech is granted via a trigger, the engine has to apply
;      it to the units the player ALREADY owns -- see
;      soundrts/worldplayerbase/triggers.py::_grant_upgrade_by_trigger.
;
; The trigger syntax takes exactly ONE condition, so the difficulty test
; IS the condition: ``trigger <owner> (difficulty story) <action>``.
; Comparison forms (``(difficulty >= hard)``, ``(difficulty != easy)``,
; ...) are supported by the engine too.
;
; NOTE ON OWNERSHIP: the castle is added to ``computer2`` (Alfonso's camp)
; so that it is handed over to the player together with the rest of the
; base when the king is escorted home (objective 2 transfers the whole
; camp).  ``(add_units <square> <type>)`` places it on that square.
trigger computer2 (difficulty story) (add_units a1 aoe_castle)
trigger player1 (difficulty story) (add_units murder_holes)

; ---------------------------------------------------------------------------
; MAKE THE ENEMIES REALLY ATTACK.
;
; A ``computer_only`` slot gets a trigger-only, do-nothing AI by default
; (see doc_src/src/en/mod/mapmaking.rst "Switch to another AI"), so
; without this the Black Guard Navy would sit in its docks and Yusuf
; would hide in his castle -- the whole chapter would be a walk around
; an empty map, and the player's army would never be tested.
;
; ``(ai intermediate)`` swaps in mods/aoe2/ai.txt's
; ``berbers_intermediate`` script, which contains real ``attack`` lines
; and ``attack_ratio 120``.
;
; The six DOCKS get their AI right away: the Black Guard Navy is the
; chapter's active enemy, it raids the coast and the player has to
; fight it.
;
; YUSUF only wakes up once the king has been delivered home (the
; ``yusuf_awake`` global is set by the objective-2 trigger below).
; While the king is being rescued and escorted, El Cid stands alone
; on the battlefield as a lone 330 HP hero, and an active Yusuf would
; simply hunt him down -- which trips
; ``(key_unit_killed npc_cid_mounted) (defeat)`` and makes the whole
; chapter unwinnable before the player has even reached Yusuf.  In the
; DE original Yusuf also sits in his camp until the player comes for
; him.
; ---------------------------------------------------------------------------
trigger computer4 (timer 0) (ai intermediate)
trigger computer5 (timer 0) (ai intermediate)
trigger computer6 (timer 0) (ai intermediate)
trigger computer7 (timer 0) (ai intermediate)
trigger computer8 (timer 0) (ai intermediate)
trigger computer9 (timer 0) (ai intermediate)
trigger computer10 (global yusuf_awake >= 1) (ai intermediate)

; Objective 3: all six Black Guard Docks are destroyed.
;
; Six separate one-shot triggers count the fallen docks in the
; ``docks`` variable; a repeatable trigger then completes objective 3
; once the counter reaches six.  Six separate triggers that each
; called ``(objective_complete 3)`` would have completed the objective
; when the FIRST dock fell -- the objective has to wait for all six.
trigger player1 (enemy_building_destroyed h2 shipyard) (add_var docks 1)
trigger player1 (enemy_building_destroyed i2 shipyard) (add_var docks 1)
trigger player1 (enemy_building_destroyed i4 shipyard) (add_var docks 1)
trigger player1 (enemy_building_destroyed i6 shipyard) (add_var docks 1)
trigger player1 (enemy_building_destroyed j3 shipyard) (add_var docks 1)
trigger player1 (enemy_building_destroyed j6 shipyard) (add_var docks 1)
trigger player1 repeat (var docks >= 6) (objective_complete 3)

; Objective 4: Yusuf's base is destroyed.
;
; DE original: "forcing Yusuf to resign requires destroying his Town
; Center AND his Castle".  Both buildings are counted in the ``yusuf``
; variable and a repeatable trigger completes the objective once BOTH
; have fallen -- two separate triggers that each called
; ``(objective_complete 4)`` would have completed it after the first
; one (same pattern as objective 3 above).
trigger player1 (enemy_building_destroyed h7 aoe_castle) (add_var yusuf 1)
trigger player1 (enemy_building_destroyed h7 town_center) (add_var yusuf 1)
trigger player1 repeat (var yusuf >= 2) (do (objective_complete 4) (victory))
